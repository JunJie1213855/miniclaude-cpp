# 角色设定
你现在是一位资深的 AI Agent 框架架构师和 TUI（终端用户界面）交互专家。你需要为我们的 Agent 系统设计并实现一个健壮的「Tool Use Interceptor（工具调用拦截器）」。

# 核心任务
请实现一个能够拦截、排队、校验权限并顺序执行 Tool Calls 的拦截器。当遇到敏感或需要授权的工具调用时，必须通过 TUI 阻塞主线程并询问用户；用户授权后，再继续执行。

# 详细技术规格与需求

## 1. 队列与依赖性管理 (Sequential & Dependency Management)
- **顺序执行**：LLM 可能会一次性返回多个 Tool Use 请求，拦截器必须将它们放入队列，严格按顺序（Sequential）一个接一个地处理。
- **依赖中断逻辑**：这些工具调用之间往往存在依赖性（例如：先用 `bash` 创建文件夹，再用 `write_file` 写入文件）。如果队列中的某一个工具由于权限被拒绝（No）或执行报错，必须**立即中止（Abort）**队列中后续所有依赖该上下文的工具调用，并将“执行被用户拒绝”的状态反馈给 LLM。

## 2. 权限校验与持久化状态 (Permission & State Logic)
- **免密白名单**：支持配置不需要权限的工具（如简单的 `read_file`，默认自动通过）。
- **拦截触发**：对于需要授权的工具（如 `bash`, `write_file`, `delete_file` 等），必须触发权限询问机制。
- **状态持久化**：用户如果选择 `Yes, and never ask again`，系统需要将该工具+特定参数的组合（或基于正则表达式的规则）写入本地配置文件（如 `~/.config/aicoder/permissions.json`）。下一次遇到完全匹配的调用时，直接静默放行，不再弹窗。

## 3. TUI 界面与交互规范 (Strict TUI Specifications)
当触发权限询问时，必须在终端渲染出极度清晰且结构化的组件。请严格按照以下格式进行渲染：

```text
┌─ Permission Request ─────────────────────────────┐
│ * tool: Bash                                     │
│ * args: cmake -S . -B build                      │
│                                                  │
│ ❯ Yes                                            │
│   Yes, and never ask again                       │
│   No                                             │
└──────────────────────────────────────────────────┘



TUI 渲染特别要求（防踩坑）：

tool 字段必须是工具的函数名（如 Bash、WriteFile），绝不能显示为文件名（如 snake.html）。

args 字段必须对参数进行格式化和截断处理。如果参数是长代码（如 HTML 源码），绝不能将几百行代码直接塞进 UI，必须显示为 path: "xxx", content: "<truncated 500 chars>" 的简洁形式。如果是命令行命令，则如实显示完整的命令语句（如 cmake -S . -B build）。

全局焦点接管（Critical）：当弹窗出现时，必须是一个阻塞式的模态交互（Modal）。此时必须隐藏或禁用底部的全局聊天输入框，确保用户的键盘事件（上/下方向键切换，回车键确认）完全绑定在 Yes/No 的菜单选择上，避免 UI 状态冲突。
